# 03.1 设计原理与逻辑架构
> 模型训练层（Alpha Combiner）- 当前默认 Quarterly PIT V2；V1 Walk-forward 见附录

---
## 一、层级职责
### 1.1 核心任务
| 任务 | 说明 | 输出位置 |
|:---|:---|:---|
| 特征工程 | 加载因子数据，构造X(特征矩阵) | 内存DataFrame |
| 标签计算 | 基于真实交易时点计算y(未来收益) | 内存Series |
| 模型训练 | LightGBM回归/LambdaRank排序学习 | experiments/{exp_id}/models/ |
| 滚动验证 | Quarterly PIT 固定季度模型，防止数据泄露 | 每季度一个模型 |
| **模型融合** | **多模型动态IC加权融合（多周期组合）** | **experiments/{ensemble_id}/** |
| 预测输出 | 生成predictions.parquet供回测层使用 | experiments/{exp_id}/ |

### 1.2 职责边界
- 本层只负责模型训练，不做因子计算（在02层完成）
- 本层不做回测和绩效分析（在04层完成）
- 本层保证训练流程无数据泄露，但不保证模型一定盈利
- 本层输出预测分数，不做任何交易决策

### 1.3 版本演进

| 版本 | 时间 | 核心训练方式 | 当前状态 |
|:---|:---|:---|:---|
| V0 | 2026-03 前 | 基础 Walk-forward，无 Gap | 已废弃 |
| V1 | 2026-03-24 | 双重Gap Walk-forward + live/test 拼接 | 兼容保留 |
| **V2** | **2026-06-25** | **Quarterly PIT 固定季度模型 + Freeze 增量模式** | **当前默认** |

**为什么从 V1 升级到 V2？**

V1 存在 "历史信号被重算" 问题：每次重跑训练时，滚动窗口会漂移，旧版本中的 live 预测可能进入新版本的 test 区间，导致同一个历史日期由不同模型预测。V2 通过"每个自然季度固定一个模型"+"Freeze 增量模式"解决该问题，确保重叠日期的预测完全一致。

### 1.4 V2 设计要点

| 设计点 | V1 | V2 |
|:---|:---|:---|
| 训练窗口 | 滑动/扩展窗口 | 每个自然季度固定一个模型 |
| 预测区间 | test + live 两段拼接 | 季度即为预测区间，无 live |
| 平滑参数 | 动态估计 halflife | 固定 `smooth_halflife` |
| 历史信号 | 每次重跑会重写 | Freeze 模式下只追加新日期 |
| 输出文件 | predictions + live_predictions | 仅 `predictions.parquet` |

### 2.3 V2 季度固定模型机制

**为什么按自然季度？**

A股财报披露具有明显的季度节奏，市场状态也往往按季度切换。固定季度模型既符合基本面更新节奏，也便于实盘运维：每季度初训练一次，季度内不再重训。

```
时间轴:

2026Q1: 1月 ~ 3月  → 使用 2026Q1_model
2026Q2: 4月 ~ 6月  → 使用 2026Q2_model
2026Q3: 7月 ~ 9月  → 使用 2026Q3_model
2026Q4: 10月 ~ 12月 → 使用 2026Q4_model
```

**单个季度的数据切分（以 20d 模型为例）:**

```
horizon = 20, gap = 21

训练集              gap       验证集              gap       季度预测区
|----------------|--------|----------------|--------|----------------------|
过去3年             21天      2个月             21天      2026-04-01 ~ 2026-06-30
fit                         early stopping             只predict，不参与训练
```

### 2.4 V2 Freeze 增量模式

```
4/1 训练：生成 2026Q2_model，预测 2026-04-01 ~ 2026-04-01
         → 冻结

5/1 训练：复用 2026Q2_model，只追加 2026-04-02 ~ 2026-05-01
         → 4/1 的预测原封不动

6/1 训练：复用 2026Q2_model，只追加 2026-05-02 ~ 2026-06-01
         → 4/1、5/1 的预测原封不动

7/1 训练：进入 2026Q3，训练 2026Q3_model
         → 2026Q2 预测全部冻结
```

## 五、核心设计决策
### 5.1 为什么从 Walk-forward 改为 Quarterly PIT？

| 方案 | 优点 | 缺点 | 本项目选择 |
|:---|:---|:---|:---|
| V1 Walk-forward | 样本外测试密集 | 每次重跑重写历史信号，as-of 不一致 | ❌（兼容保留）|
| **V2 Quarterly PIT** | **同一季度固定模型，历史信号可冻结** | 季度初需重新训练 | ✅（当前默认）|
| 组合交叉验证 | 稳健性高 | 复杂度高，实现困难 | ❌ |

理由：
- 金融策略的实盘信号必须是 point-in-time 的，生成后不能修改
- V2 保证同一个历史日期在不同 as-of 运行中使用同一季度模型，预测完全一致
- 冻结模式使 4/1 能看到的信号在 5/1、6/1 重跑后不被改写

### 5.2 为什么标签用开盘价而非收盘价？
| 方案 | 买入时点 | 卖出时点 | 公式 | 实盘可执行性 |
|:---|:---|:---|:---|:---|
| 收盘价标签 | T日收盘 | T+20日收盘 | close[t+20]/close[t] - 1 | 差（无法T日收盘下单）|
| 开盘价标签 | T+1开盘 | T+(horizon+1)开盘 | open[t+h+1]/open[t+1] - 1 | ✅ 好（真实可执行）|

V2 继续沿用 open-to-open 标签。

### 5.3 为什么 V2 固定 smooth halflife？

V1 使用 `calc_halflife(df_pred)` 基于整段预测历史的自相关动态估计半衰期。加入新日期后，halflife 会变化，导致历史 EMA 平滑值微调。

V2 默认固定 `smooth_halflife = 10`：
- 降低因子换手率
- 避免每次重跑时历史 smooth 被重算
- 半衰期作为显式超参数，便于实验对比

### 5.4 为什么 V2 不再生成 live_predictions？

V1 需要 live_predictions 是因为 test 区间结束后仍有未来日期需要预测。V2 把每个季度都作为预测区间，只要数据可用，季度内所有交易日都在 `predictions.parquet` 中输出，无需单独的 live 文件。

这也消除了 V1 中 test/live 分界移动导致的信号重算问题。

### 5.5 为什么支持两种模型（回归+排序）？
| 模型 | 适用市场状态 | 特点 |
|:---|:---|:---|
| 回归 | 收益分布均匀，无明显极端值 | 直接预测收益数值 |
| LambdaRank | 收益两极分化，头部效应明显 | 聚焦排名，忽略绝对值 |

## 六、关键概念解释
### 6.1 IC（信息系数）
```python
# Pearson IC
ic = predictions.corr(actual_returns)

# Rank IC (Spearman)
rank_ic = predictions.corr(actual_returns, method='spearman')
```

### 6.2 Quarterly PIT 窗口配置
```
train_window='3Y'  → 约756个交易日
valid_window='2M'  → 约42个交易日
gap = horizon + 1  → 21个交易日（20d模型）

模型数量：每季度一个
```

### 6.3 Early Stopping（早停）
验证集用于早停决策，不参与模型参数学习。测试集（即季度预测区）只用于最终评估。

### 6.4 特征重要性
V2 特征重要性按季度保存，文件名包含 `importance_{YYYYQn}_fold_{id}.csv`，便于追踪特征重要性的时序变化。

## 附录 A：V1 Walk-forward 详细设计

V1 仍保留在代码库中，用于兼容旧实验。新实验请使用 V2。

### A.1 V1 架构
```
时间轴:  2010    2015    2020    2024
                               
Fold 0: [训练]──→[Gap]──→[验证]──→[Gap]──→[测试]
           2010-2014              2014Q3       2014Q4
Fold 1:     [训练]──→[Gap]──→[验证]──→[Gap]──→[测试]
             2010Q2-2014Q2            2014Q4       2015Q1
```

### A.2 V1 双重 Gap 机制
```
gap = label_horizon + 1 = 21天（20d模型）

Train: ... 2024-01-31
Gap:   2024-02-01 ~ 2024-02-29 (21个交易日)
Valid: 2024-03-01, 2024-03-02, ...
```

### A.3 V1 已知问题
- live/test 分界会随数据截止日移动
- 每次重跑会重新生成所有 fold 的 test 预测
- 动态 halflife 导致历史 smooth 微调
