## 一、关键检查点
### 1.1 输入
| 检查项 | 通过标准 |
|:---|:---|
| 实验目录 | 存在 |
| 预测文件 | 存在且可读 |
| 预测列 | 与`--use-smooth`一致 |
| 行情宽表 | 日期和股票覆盖预测 |
| ST状态 | 正式验收必须来自Tushare路径 |
| 回测区间 | 不超过预测和行情交集 |

### 1.2 Alphalens
- 清洗后样本数量合理
- 分位数组完整
- Rank IC不存在全空
- Top/Bottom组方向合理
- 平滑前后换手差异可解释

### 1.3 Backtrader
- 首末调仓日正确
- 每月只有一个调仓截面
- 主板、ST和涨停过滤数量合理
- `rebalance_signals.csv` 与实际订单一致
- 手续费参数明确
- 报告不声称存在未配置滑点
- 止损按20%执行

### 1.4 结果
| 指标 | 用途 |
|:---|:---|
| 累计/年化收益 | 收益能力 |
| Sharpe | 风险调整后收益 |
| 最大回撤 | 风险 |
| 胜率和盈亏比 | 交易质量 |
| 交易数量 | 样本有效性 |
| 换手 | 成本敏感性 |

历史结果不能直接作为 Tushare 重训后的正式结论。

## 二、标准运行流程
### 2.1 Alphalens
```powershell
python 04回测层/alphalens_analysis.py `
  --exp-id <exp_id> `
  --periods 20 `
  --quantiles 10 `
  --use-smooth
```

检查：

```text
reports/{exp_id}/alphalens_report_smooth.html
```

### 2.2 Backtrader
在正式运行前确认第四层 ST 路径已经迁移。

```powershell
python 04回测层/backtrader.eval.py `
  --exp-id <exp_id> `
  --use-smooth
```

检查：
- `rebalance_signals.csv`
- `trades.csv`
- `equity_curve.png`
- `backtest_report.html`

### 2.3 原始与平滑对比
分别运行：

```powershell
python 04回测层/alphalens_analysis.py --exp-id <exp_id>
python 04回测层/alphalens_analysis.py --exp-id <exp_id> --use-smooth
```

比较：
- Rank IC
- IC IR
- 分层收益
- 信号稳定性

Backtrader 同样分别运行原始和平滑预测。

## 五、故障排查
| 现象 | 检查 |
|:---|:---|
| IC为空 | 预测日期、价格日期、periods |
| 分层组数不足 | 每日有效股票数 |
| Backtrader无交易 | 调仓日、TopN、过滤后股票数 |
| ST过滤无效 | 实际读取路径和日期覆盖 |
| 收益异常高 | 成交时点、涨停、费用和未来信息 |
| 实盘信号报文件不存在 | V2无live_predictions |
| 回测与候选信号不一致 | 两份脚本逻辑尚未统一 |
